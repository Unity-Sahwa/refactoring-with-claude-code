## 구현 검토 문서 작성
- `Assets\1. Code\Docs\3. Implement` 위치에 구현 검토 문서를 생성한다.
- 구현담당은 설계를 어떻게 구현할지 문서에 작성한다.
- 문서는 매우 간략하게, 시각적으로 표현되게, 정리되게 작성한다.

1. 구현 클래스/메서드들의 동작 흐름을 다이어그램으로 작성
2. 어떤 기능들이 들어가는지 매우 간략하게 작성
3. 단점, 문제, 주의사항을 최대한 개선할 수 있는 방식을 제안.

- 해당 문서를 사용자에게 평가받고 수정한다.
- 이후 구현 승인이 난다면 본격적인 구현을 시작한다.

## 코드 구현
- `Assets\1. Code\Scripts` 위치에 폴더(시스템 이름으로) 생성 후 코드 구현 문서를 생성한다.
- 클래스간의 직접 참조를 금지한다.
- 하드코딩, 나열식 구현을 금지한다. 반복되는 코드는 지양한다.

- 클래스 단일 책임 원칙: 하나의 클래스는 하나의 이유로 변경이 되어야 한다.
- 개방 폐쇄 원칙: 수정에 닫혀있고, 확장에 열려있다.
- 만들어진 자식 클래스는 부모를 대체할 수 있어야 한다.
- 인터페이스 분리 원칙: 인터페이스 구현시 내부 기능은 무조건 사용할 정도로 세부적으로 나눈다.
- 의존성 역전 원칙: 의존은 추상적으로 해야한다. 직접 소통은 절대 금지
- 유니티 엔진에 최적화된 설계를 한다.
- 유지보수, 확장, 단위 테스트를 고려하여 설계한다.

- 코드 작성 규칙은 해당 경로를 준수한다. `Assets\1. Code\Docs\_Convention\UnityCode.md`
- `Assets\1. Code\Scripts` 위치에 폴더(시스템 이름으로) 생성 후 코드 스크립트를 저장한다.
