플레이어 FSM 시스템을 구현하고 있다. 상태매니저에서 상태 클래스를 생성하고 상태 매니저의 Update에서 상태 클래스의 UpdateState()를 실행한다.
-> 상태 클래스는 매프레임 UpdateState()를 실행하면서 현재 캐릭터의 애니메이션 진행률을 탐지하고 원하는 타이밍에 이벤트를 호출하고자 한다.

### 필요사항
- 특정 타이밍을 나타내는 float 값을 SO 데이터에셋에서 가져와야 한다.
- 특정 타이밍에 이펙트, 히트박스, 오디오 등 필요한 클래스가 메서드를 호출할 수 있어야 한다.

### 추상화적 설계
1. StateManager에 IStateDataProvider, 애니메이터,  AnimationEventBus를 제공
2. 데이터 에셋, 애니메이터, AnimationEventBus를 조합하여 상태 클래스에 제공
3. 상태 클래스에서 애니메이션 진행되는 동안 타이밍에 맞춰 원하는 이벤트 호출

### 디테일한 설계

- DIContainer에서 IStateDataProvider(StateDataManager)를 StateManager의 Inject 메서드를 통해 제공. Awake() 단계에서 제공(가장 빠른 Awake() 임)
- 필요한 애니메이터 Inspector에서 드래그앤드랍 (나중에 캐릭터 스위치 관리 클래스에서 현재 실행되는 애니메이터 제공)
- DIContainer에서 AnimationEventBus를 StateManager의 Inject 메서드를 통해 제공. Awake() 단계에서 제공(가장 빠른 Awake() 임)

### [인사이트]
- 플레이어 시스템 전체가 문제였기 때문에 구체적으로 문제를 정의하려면 여러 곳을 고민해야 한다. 그렇기 때문에 AI에게 해당 부분만 구체적으로 문제를 정의하여 해결하는게 어려웠다.

- 사실 나조차도 제대로 정의를 하지 못해서 이 상태로 AI에게 구현해줘, 설계해줘, 대답해줘 하면 동문서답이 나오는 경우가 많다. 어쩌면 AI가 장문으로 해결책을 줘도 읽기 싫어 잘 안읽힌다.

- 대답을 하나씩 분해하거나 문제를 잘 정의할 필요성을 느꼈다. 문제가 무엇인지는 알고 어떤 방향으로 구현하고 싶은지는 알지만 디테일한 구현을 위해서라면 문제정의 또한 디테일하게 하여 나의 의도를 AI에게 전달하는 노력을 할 것이다.
