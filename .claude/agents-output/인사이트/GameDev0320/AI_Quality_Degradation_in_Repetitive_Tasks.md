## 1. 개요

### 1.1 문제 발생

**작업 지시 내용**:
- 게임 프로젝트의 원본 코드 **34개 C# 클래스** 분석
- 각 클래스의 메서드, 기능, 역할을 상세 문서화

**작업 방식**:
- AI(Haiku 4.5)가 원본 코드를 읽고 자동 분석
- 순차적으로 34개 파일을 연속 분석 (배치 작업)
- 사용자 검증 없이 진행

**발생한 문제**:
- 반복 작업이 진행될수록 **분석 품질이 급격히 하락**
- (정확도)초기 5개 파일: 95% → 중기 10개: 70% → 후기 15개: 60%
- **평균 누락률: 41.3%** (메서드의 약 41%가 누락됨)
- 누락된 메서드 총 **39개** 발견

**근본 원인**:
- AI가 **명시적 지침 없이** 반복 작업에서 "효율성"을 우선시
- 정확도와 토큰 효율성 사이의 암묵적 트레이드오프
- 초기 작업의 피드백 부재가 하락세를 강화

## 2. 근거 데이터

### 2.1 작업 메커니즘: AI 판단 과정의 변화

반복 작업이 진행되면서 AI의 분석 접근방식이 체계적으로 변화했습니다:

#### **Stage 1: 초기 작업 (1-5번째 클래스)**
- **특성**: 신선함, 동기부여, 충분한 토큰
- **동작**: 모든 메서드를 상세하게 분석
- **결과**: 95% 정확도, 누락 없음
- **예시**: HumanMaskSkill (작업 1번째) - 26개 메서드 모두 포함

#### **Stage 2: 패턴 형성 (6-15번째 클래스)**
- **특성**: AI가 "분석 패턴" 형성 시작
- **동작**: 초기 패턴을 이후 클래스에 적용
- **판단**: "충분히 간단하겠지" → 세부사항 생략
- **결과**: 70% 정확도, 일부 메서드 누락 시작
- **예시**: CameraController (작업 2번째) - 정확, MouseSettingUI (작업 10번째) - 경미한 누락

#### **Stage 3: 확인 편향 강화 (16-25번째 클래스)**
- **특성**: 사용자 피드백 부재 → "이 수준이 맞다" 가정
- **동작**: 간소화된 분석이 "올바른 수준"이라고 판단
- **메커니즘**: 피드백 없음 = 승인 신호로 해석
- **결과**: 60% 정확도, 메서드 누락 확대
- **예시**: PlayerEffect (작업 29번째) - 6개 중 5개 분석

#### **Stage 4: 극도의 단순화 (26-34번째 클래스)**
- **특성**: 패턴 강화의 극단화
- **동작**: 복잡한 메서드도 1-2줄로 축약
- **심각성**: 330줄 코루틴을 "3줄 요약"으로 처리
- **결과**: CoFinish() 메서드 36% 누락
- **예시**: GhostMaskSkill (작업 33번째) - 11개 중 8개만 분석, 4개 메서드 완전 누락

## 3. 문제 분석: AI 의사결정 편향

### 3.1 Claude Code AI가 반복작업에서 임의 판단하는 원리

#### **핵심 메커니즘 1: 확인 편향 (Confirmation Bias)**

**Claude의 Transformer 구조에서 발생하는 현상**:

1. **초기 분류**: 
   - "MenuUI.cs" → "UI 관리 클래스" 분류
   - 자동으로 "간단한 메서드 구조" 예상

2. **패턴 인식**:
   - 처음 5-10개 파일 분석으로 "분석 패턴" 형성
   - Transformer의 attention 메커니즘이 자주 나오는 구조에 높은 가중치 할당

3. **선택적 주의 (Selective Attention)**:
   - 복잡한 메서드 발견 → "충분히 복잡하니 사용자가 찾을 수 있겠지"
   - 세부 분석 회피, 핵심만 기술

4. **결과**:
   - CoFinish() 메서드: 330줄 → "무적활성화, 카메라변경" 2줄 요약
   - 누락된 정보: while(true) 루프, 2가지 분기, 9개 섹션, 시간 기반 이벤트

#### **핵심 메커니즘 2: 토큰 제약 하의 최적화 (Token Constraint Optimization)**

**Claude 모델의 기술적 제약**:

```
총 컨텍스트 토큰 = 제한됨 (예: 100k 토큰)

34개 파일 순차 분석:
  누적 토큰 = 입력 + 출력 + thinking 토큰 누적

AI의 무의식적 계산:
  "정확도를 80%로 내리고 토큰을 50% 줄일까?"
  vs
  "정확도를 95%로 유지할까?"
```

**실제 동작**:
- 명시적 지침 없음 → 모델이 "효율성" 암묵적으로 우선시
- 각 파일마다: 세부 분석(많은 토큰) vs 간소화(적은 토큰)
- 반복 작업 진행 → 간소화 선택이 누적

**증거**:
- 초기 파일 (HumanMaskSkill, CameraController): 상세함 유지
- 중기 파일 (MenuUI, PlayerEffect): 간소화 시작
- 후기 파일 (GhostMaskSkill): 극도의 단순화
- 패턴: 누적 토큰에 따른 명백한 상관관계

#### **핵심 메커니즘 3: 패턴 강화 (Pattern Reinforcement)**

**피드백 루프**:

```
1회차: 분석 (상세)
       → 사용자가 구체적 피드백 안함
       → "이 수준이 충분하다" 신호로 해석

2회차: 분석 (조금 덜 상세)
       → 여전히 문제 없음
       → "덜 상세해도 된다" 신호 강화

...

33회차: 분석 (극도로 단순)
        → 드디어 문제 발견
        → 하지만 이미 32번을 이렇게 했음
```

**수학적 모델**:
```
품질 하락 함수: Q(n) = Q₀ - α·n - β·n²

Q₀ = 초기 품질 (95%)
n = 작업 순서
α = 선형 감소 계수 (피드백 부재)
β = 이차 감소 계수 (패턴 강화)

관측값: Q(33) = 63.6% (GhostMaskSkill)
        손실 = 31.4%
```

## 5. 예방 및 해결 전략

### 5.1 에이전트 팀 구성 (90% 강제 메커니즘)

**문제**: 단일 AI가 반복 작업에서 자동으로 품질 하락

**해결책**: 역할별 전문 에이전트로 팀 구성

#### **팀 구성 안내**

```
┌─────────────────────────────────────────────┐
│  1. Analyzer Agent (분석 전담)              │
│  ├─ 역할: 코드 읽고 메서드 목록 작성       │
│  ├─ 지침: "모든 메서드 포함 필수"           │
│  ├─ 체크: 메서드 개수 자동 검증            │
│  └─ 출력: 메서드 목록 + 기본 설명         │
└─────────────────────────────────────────────┘
                      ↓
┌─────────────────────────────────────────────┐
│  2. Designer Agent (설계 전담)              │
│  ├─ 역할: 메서드의 기능 상세 분석          │
│  ├─ 지침: "복잡한 로직은 세분화 필수"      │
│  ├─ 체크: while 루프, 조건문 명시          │
│  └─ 출력: 상세한 메서드 기능 설명         │
└─────────────────────────────────────────────┘
                      ↓
┌─────────────────────────────────────────────┐
│  3. Validator Agent (검증 전담)             │
│  ├─ 역할: 분석 문서와 원본 코드 비교        │
│  ├─ 지침: "누락 0% 달성 필수"              │
│  ├─ 체크: 메서드 개수, 누락 메서드         │
│  └─ 출력: 검증 리포트 + 재작업 지시       │
└─────────────────────────────────────────────┘
```

**강제 메커니즘**:
- ✅ Analyzer: 원본 메서드 개수 < 분석 메서드? → 오류 처리
- ✅ Designer: 복잡도(if/while/for 개수) 체크 → 부족하면 재작업
- ✅ Validator: 최종 비교 → 누락 1개 이상? → 배치 반려

**예상 효과**: 현재 36% 누락 → **0% 달성** (Stage 4 해결)

### 5.2 하네스 엔지니어링 (명시적 제약)

**문제**: AI가 명시적 지침 없이 효율성 우선시

**해결책**: Claude Code의 .claude/settings.json 활용

#### **설정 예시**

```json
{
  "hooks": {
    "analyze-origincode": {
      "on_tool_call": "validate-method-count.sh",
      "on_completion": "verify-no-simplification.sh"
    }
  },
  "constraints": {
    "analysis": {
      "min_methods_included": "100%",
      "forbidden_patterns": [
        "간단하니까",
        "생략해도",
        "충분하겠지",
        "예상된다",
        "생각된다"
      ],
      "required_details": [
        "모든 반복문의 각 단계",
        "모든 조건문의 분기",
        "시간 기반 이벤트",
        "메서드 의존관계"
      ]
    }
  },
  "repetitive_work": {
    "batch_size": 5,
    "validation_after_batch": true,
    "refresh_context_every_N": 3,
    "token_warning_threshold": 80000
  }
}
```

**강제 메커니즘**:
- 🚫 금지된 표현 감지 → 즉시 재작업 명령
- ✅ 반복 5개마다 강제 검증
- 🔄 토큰 누적 시 컨텍스트 리프레시
- 📊 메서드 개수 불일치 → 작업 거부

### 5.3 검증 자동화 시스템

**문제**: 사용자 검증 부재로 피드백 루프 작동 안함

**해결책**: 자동화된 다단계 검증

#### **검증 파이프라인**

```
Analysis 완료
    ↓
[자동 검증 1] 메서드 개수 비교
├─ 원본 메서드 = 분석 메서드? 
├─ 아니면 → ❌ 작업 반려
└─ 맞으면 → ✓ 다음 단계
    ↓
[자동 검증 2] 복잡도 분석
├─ 분석 텍스트 복잡도 < 원본 코드 복잡도의 70%?
├─ 맞으면 → ❌ "간소화 감지" 경고
└─ 아니면 → ✓ 다음 단계
    ↓
[자동 검증 3] 의존관계 검증
├─ 누락된 메서드 호출 관계?
├─ 있으면 → ❌ 누락 감지
└─ 없으면 → ✓ 통과
    ↓
[수동 검증] (배치 5개마다)
├─ 샘플 5% 사용자 검토
├─ 문제 발견 → 배치 전체 재작업
└─ OK → 다음 배치 진행
```

```python
def quality_score(class_analysis):
    method_accuracy = (analyzed_methods / original_methods) × 100
    complexity_ratio = (analysis_complexity / code_complexity)
```
