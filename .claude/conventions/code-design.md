> 대화 시, 각 단계 관련 활동을 할 때만 해당 헤더 내용을 복붙해서 AI와 규칙을 공유한다.

# 1. 수집
- 주제 정하기
- 기존에 존재하는 관련 기능을 한곳에 모으기 (클래스·메서드의 코드 일부 형태로, 변수 포함)
- `.claude/activities` 하위에 시스템 폴더 생성
- 시스템 폴더에 파일 생성

# 2. 분석
- 기존 기능의 흐름 파악하기
- 어디가 문제인가
- 어디가 비효율/효율적인가
- 새로운 설계에 참고할 만한 기능이 있는가
- 시스템 폴더에 파일 생성

## 2-1. 분석 결론
- 이번 설계에서 반드시 해결할 문제를 1~3개로 압축
- 손대지 않을 부분(범위 밖) 명시

# 3. 설계

## 3-1. 계획
- 유지할 기능과 신규 기능 리스트업하기
- 각 기능의 확장 방향
- 현재 설계된 시스템과 어떻게 연결하고, 어떻게 아웃풋을 내는지
- 어떤 외부 기능들과 연결되어야 하는지
- 파일 생성

## 3-2. 초안
- 시작(연결)과 아웃풋은 정해졌다. 이 설계가 어떤 흐름을 가지면 좋을지 대충 흐름 만들기
- 빈 클래스·빈 메서드 만들어보기 (클래스명·메서드명 모두 한글로, 무엇을 할지 주석으로 작성)
- 세세하게 설계하지 않는다
- 코드를 실제로 작성하지 않는다
- 계획 파일에 함께 작성

## 3-3. 특성
- 금지사항 정의
- 필수사항 정의
- 테스트 정의 (테스트 목적 포함)
- 비용 정의
    - 성능·비용에 대한 수치적인 결과 도출이 가능한지
- 저사양 정의 ()
- 저사양 정의 (목표 최저 사양에서 동작 보장 기준 — 예: 30fps 유지, GC 스파이크 없음)
    - 어떤 기기/프레임을 최저선으로 잡는지
    - 그 환경에서 깨지면 안 되는 동작은 무엇인지
- 좋은 코드 정의
- 좋은 설계 정의
- 파일 생성 (설계할 때마다 재활용하니 계속 쌓아나가기)

## 3-4. 활동
- 진짜 설계를 진행하는 단계
- 계획과 초안을 바탕으로 만들기
- 코드 작성이 아님
- 게임 상황을 가정하고 흐름을 반복해서 흘려보며 의문·문제 등을 계속 파헤치기
- 클래스 간 연결 방식, 무엇을 어떻게 주고받을지까지 포함해 작성
- 게임 상황 시나리오를 1개씩 잡고, 그 흐름을 클래스/메서드 호출 순서로 따라가 보기
- 각 단계에서 "이 값을 누가 주는가 / 없으면 어떻게 되는가"를 질문으로 적기
- 막히는 지점(분기·예외·동시성)을 표시하고 초안 클래스에 메모로 남기기
- drawio 사용

## 3-5. 검토
- 특성을 바탕으로 검토
- 피드백 후 설계 수정

## 3-6. Git Issue 작성

# 4. 구현

## 4-1. Git Commit
- 자주 하기
- Commit을 통해 사용자가 로직을 이해할 수 있어야 함

## 4-2. 테스트
- 다 만들어진 구현 코드로 테스트 활동하기
- 유의미하고 수치적인 결과가 나오게 하려면 어떻게 할까

## 4-3. 평가
- 구현된 코드를 보고 설계 평가 받기
- 설계 수정이 필요하면 하고, 구현도 수정하기

## 4-4. Git Issue / Milestone / PR 수정 및 작성
