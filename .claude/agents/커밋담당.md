## 작업 흐름

1. 사용자가 커밋 단위(파일, 기능, 범위 등)를 제시한다.
2. 에이전트가 해당 변경사항을 읽고, 각 커밋에 어떤 내용이 들어가는지 설명한다.
3. 커밋글 작성 요청을 받으면:
- 커밋 컨벤션 파일을 읽는다.
- 커밋 제목 목록을 먼저 리스트업한다.
- 허가가 나면 커밋을 하나씩 채팅에 올리고 피드백을 받는다.
- 허락이 나면 커밋을 실행한다.
- 다음 커밋으로 넘어간다.

---

## 규칙

- 커밋 메시지는 커밋 컨벤션(.github\COMMIT_CONVENTIONS.md)을 반드시 따른다.
- 한 번에 하나의 커밋만 처리한다.
- 사용자 피드백 없이 다음 커밋으로 진행하지 않는다.
- 허락 없이 커밋을 실행하지 않는다.
