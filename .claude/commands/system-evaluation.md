# 시스템 평가

> `Assets/1.Code/Scripts/` 바로 아래 각 폴더가 ``시스템``의 단위다. 시스템 내부의 폴더는 `기능`의 단위이다.
클래스가 해당 시스템/기능에 포함되는게 맞는지 평가한다.

---

## 0. 절차

1-1. 사용자로부터 파일을 지목받는다.
1-2. 해당 파일을 컨텍스트에 올린 다음 1절 축으로 평가한다. 외부 연결 여부(개발자용)·에디터 작업 필요 여부(비개발자용)도 표시해 개수를 센다.
1-3. 2절 판정표와 활용 표시를 출력한다. 판단이 갈리는 부분은 이때 사용자에게 질문한다.
1-4. 판정표에 `FAIL`이 나와있다면 해당 문제는 사용자와 대화하여 개선한다.
1-5. 개선 후 판정표에 `FAIL`이 없다면 1-1로 되돌아간다. 시스템 내부 파일을 전부 평가하거나, 사용자가 중단한다면 다음 단계로 넘어간다
2. 3절 형식으로 `Docs/SystemUsageGuide.md` 항목 초안을 만든다. 1-2에서 센 개수와 초안의 클래스 나열 수를 맞춘다. 다르면 빠진 클래스를 채운다.
3. **초안을 사용자에게 보여주고 승인을 받으면 `Docs/SystemUsageGuide.md`에 작성한다.

---

## 1. 평가 축

### 1-1. 시스템 간의 연결
| 질문 | PASS | FAIL |
|---|---|---|
| 외부 시스템의 class, enum, struct, abstract을 직접 참조했는가? | 참조 안했다. | 참조 했다. |
| 참조한 인터페이스의 반환타입·매개변수가 외부 시스템의 class/enum/struct/abstract인가?" | 아니다 | 맞다 |

> 예외: DISystem의 `[Inject]`, `[Inject(true)]` 어트리뷰트 참조는 PASS로 본다.
> 단, 어트리뷰트로 주입받는 필드의 타입은 예외 없이 그대로 검사한다.


### 1-2. 시스템 내부 기능 간의 연결
| 질문 | PASS | FAIL |
|---|---|---|
| 다른 기능 폴더에 정의된 class/enum/struct/abstract를 직접 참조했는가? (시스템 루트의 공용 타입은 제외) | 안했다 | 했다 |
| 참조한 인터페이스의 반환타입·매개변수가 다른 기능 폴더에 정의된 class/enum/struct/abstract인가? (시스템 루트의 공용 타입은 제외) | 아니다| 맞다 |


### 1-3. 기능 배치 적합성
| 질문 | PASS | FAIL |
|---|---|---|
| 이 클래스가 다른 기능 폴더/다른 시스템에 정의된 구체 abstract 클래스를 상속하는가? | 아니다 | 맞다 |
| 이 클래스가 자기 기능 폴더의 다른 클래스는 하나도 안 참조하고, 외부 시스템/기능만 참조하는가? | 아니다 | 맞다 |

> 확장성(새 종류 추가 시 기존 코드 안 고치나)과 트러블슈팅(원인이 좁혀지나)은 클래스 단위 품질이라
> `code-evaluation`이 담당한다. 여기서 다시 보지 않는다.

## 2. 판정표 출력

1절의 모든 핵심 질문을 빠뜨리지 않고 옮긴다.

| 판정 | 축 | 질문 | 근거 (파일:줄) |
|---|---|---|---|
| FAIL | 1-3 | 다른 기능 폴더/다른 시스템에 정의된 구체 abstract 클래스를 상속하는가? | SoundSettings.cs:38 — SettingSystem의 SettingsHolder를 상속 |

- 판정은 `PASS` / `FAIL` 둘 중 하나.
- `FAIL`에는 반드시 파일:줄 근거를 적는다. 근거 없으면 적지 않는다.

판정표 아래에 활용 표시를 붙인다. 3절 초안에서 클래스를 빠뜨리지 않기 위한 표다.

| 구분 | 있음/없음 | 내용 |
|---|---|---|
| 해당 클래스가 외부 시스템에서 참조되는가? | 없음 | AudioPlayer만 `TryGet`을 부름 |
| 해당 클래스가 씬 배치·SO 에셋 생성·인스펙터 값 입력을 요구하는가? | 있음 | SO 에셋 생성, `_entries`에 SoundType별 클립·볼륨 입력, DataContainer 등록 |

---

## 3. Docs/SystemUsageGuide.md 항목 작성

- 만약 판정표의 FAIL이 0건일 경우, 시스템 활용 방안 초안을 아래의형식으로 대화창에 작성한다.
- 사용자의 승인에 따라 SystemUsageGuide에 초안을 적용한다.

```
## <시스템명>
- 이 시스템이 프로젝트에서 무슨 역할을 하는지 한줄 작성

### 이 시스템을 활용하는 방법 (개발자용)
- 외부와 연결되는 클래스·인터페이스·SO를 나열함
- 클래스마다 받아쓰는 방법과 제공 기능을 표로 적음
- 제공 기능 없으면 `없음`으로 표시

### 이 시스템을 활용하는 방법 (비개발자용)
- 에디터 작업이 필요한 클래스(SO 에셋, 씬 컴포넌트 등)를 나열함
- 클래스마다 만드는 법(메뉴 경로/컴포넌트 추가), 배치 위치, 채울 수치(SO 필드 또는 SerializeField)를 적음
- DataContainer 등록이 필요한 SO면 그것도 적음
```
