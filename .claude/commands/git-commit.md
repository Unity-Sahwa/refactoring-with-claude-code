# /git-commit

사용자는 파일 목록을 주지 않는다. 저장소를 직접 읽어서 판단한다.

## 1. 수집
- `git status --porcelain`, `git diff`, `git diff --cached`
- `git log --oneline -10`
- `gh issue list --state open`

## 2. 변경사항 분류
- 파일 단위가 아니라 **논리 단위**로 묶는다. 무관한 변경이 섞였으면 커밋을 쪼갠다.
- 제목에 쓸 시스템명은 **변경의 원인이 된 시스템** 하나로 정한다. 딸려 바뀐 시스템은 본문에 적는다.
- 코드 밖 변경은 `[Docs]` `[Chore]` `[Assets]` 중 하나.
- **코드 파일(.cs)과 비코드 파일(프리팹·씬·에셋·문서·설정 등)은 같은 커밋에 섞지 않는다.** 원인이 같아도 종류가 다르면 쪼갠다. 비코드끼리도 종류가 다르면(예: 문서 vs 씬) 섞지 않는다.

## 3. 이슈 매칭
- `gh issue list --state open` 결과를 보여주고, 이 묶음을 어느 이슈에 넣을지 사용자에게 묻는다. AI가 임의로 짝짓지 않는다.
- **맞는 이슈가 없으면 거기서 멈춘다.** 이슈·마일스톤 생성은 이 커맨드의 일이 아니다. `/git-issue` 실행을 권하고 대기한다.
- 사용자가 "이슈 없이 커밋"이라고 하면 이슈 참조 없이 진행한다.
- 이슈가 정해지면 **이번 커밋으로 그 이슈를 닫을 것인지** 묻는다.
  - develop 등 default 브랜치가 아닌 곳은 `Closes`가 자동 발동하지 않으므로, 닫기로 했어도 꼬리말은 `Refs #N`으로 쓰고 대신 Project Status를 `Done`으로 바꾼다.
  - 닫기로 했으면, 커밋·푸시가 끝난 뒤 `/git-issue`를 불러 그 이슈에 달린 `Refs #N` 커밋들을 모아 이슈 본문을 채우게 한다.

## 3-1. 태그 판정
- `Docs/Tags.md`를 읽고 시스템·커맨드/스킬·개념·상태 4개 범주에서 후보 태그를 뽑는다.
- 뽑은 후보를 커밋안(4번)에 적어 사용자에게 확인받는다. AI가 임의로 확정하지 않는다.
- 맞는 태그가 없으면 **`Docs/Tags.md`에 새 행을 먼저 추가**한 뒤 그 태그를 쓴다. 같은 뜻의 태그를 새로 만들지 않는다.

## 4. 커밋안 제시 → 1차 승인
**한 번에 한 커밋만 제시한다.** 묶음이 여러 개여도 첫 묶음만 보여주고, 그 커밋이 push될 때까지 나머지는 꺼내지 않는다. 전체 묶음 개수만 한 줄로 알린다.

```
## 커밋 N
파일: (전체 나열, 생략 없이)
  <경로1>
  <경로2>
  ...
이슈: #98 (닫음 → Done | 안 닫음 → Refs)
태그: #disystem #system-evaluation
메시지:
  <아래 메시지 규칙대로>
```

## 5. 승인 후 — 바로 커밋·푸시
1. 승인 전에는 `git add`를 하지 않는다. 승인은 매번 그 직전 상태 기준이다 — 이전에 승인받은 커밋이라도 push 전까지는 인덱스에 그대로 두지 않는다(4번 참고).
2. `git add` 직전에 `git status --porcelain`으로 인덱스를 확인한다. 앞자리 글자(스테이징 상태)가 공백이 아닌 파일, 즉 이미 스테이징된 파일이 있으면 전부 이번 커밋안의 파일 목록과 대조한다.
   - 전부 이번 목록에 있는 파일이면 그대로 진행한다.
   - 목록에 없는 파일이 하나라도 있으면 **그 파일들을 먼저 `git restore --staged`로 내려놓는다.** 누가 언제 올렸는지 알 수 없는 채로 같은 커밋에 묶으면 안 된다. 내려놓고도 사용자가 직접 올린 것인지 의심되면 진행 전에 물어본다.
3. 이번 커밋 파일만 `git add`하고, **커밋은 파일 목록을 pathspec으로 못박아** 곧바로 진행한다 — `git add`와 `git commit` 사이에 다른 작업을 끼우지 않는다. 그 이슈의 첫 커밋이면 Project Status를 `In Progress`로 바꾼다.
4. 커밋과 푸쉬는 **Bash 툴으로 아래 형태만** 쓴다. PowerShell here-string(`@'...'@`)을 쓰면 메시지 앞뒤에 `@`가 들어간다. `-- <경로...>`에는 4번 커밋안에 적은 파일을 전부, 그것만 적는다 — 인덱스에 다른 게 섞여 있어도 이 커밋에는 안 들어가고 스테이징된 채로 남는다.

   ```
   git commit -F - -- <경로1> <경로2> ... <<'EOF'
   <제목>

   <본문>
   EOF
   git show --stat --name-only HEAD
   ```
5. 방금 커밋의 파일 목록(`git show` 결과)이 4번 커밋안의 목록과 정확히 같은지 대조한다. 하나라도 다르면 **push하지 않고 멈춘다** — `git revert --no-edit HEAD`로 그 커밋만 되돌리고 원인을 보고한다. 같으면 `git push`한다.
6. 3번에서 닫기로 정했으면 Project Status를 `Done`으로 바꾸고(`gh project item-edit`), `/git-issue`를 불러 이슈 본문을 채우게 한다. 이슈 자체는 열린 채로 둔다 — 실제 close는 default 브랜치 머지 때 일어난다.
7. push까지 끝나면 그때 다음 묶음을 4번부터 다시 시작한다.

## 메시지 규칙

```
[InputSystem] 입력 잠금을 상태 폴링에서 이벤트 수신으로 교체

- 매 프레임 상태를 폴링해 상태 전이 직후 1프레임 입력이 새고 있었기 때문에, **InputHub가 상태 변경 이벤트를 직접 받게 바꿔 폴링 자체를 없앰**
- 이벤트 순서가 꼬일 위험은 남았지만, **폴링을 남기면 같은 버그가 반복되므로 순서 보장은 InputHub 쪽에서 처리함**

Closes #98
#inputsystem #bugfix #problemsolved
```

**제목**
- 기존 것을 바꾼 커밋: `[{시스템명}System] {대상}을 {이전}에서 {이후}로 {행위}`. 50자 이내, 마침표 없음.
- 없던 것을 만든 커밋: `[{시스템명}System] {대상}이 {무엇을 하게} {추가}`. 새로 넣은 것에는 `{이전}`이 없으므로 교체형을 억지로 쓰지 않는다.
- 제목은 코드를 안 본 사람이 읽는다. 필드명·클래스 내부 용어·영어 직역(`픽셀 예산`, `플래그 해제`)을 그대로 옮기지 말고, 그 코드가 실제로 만드는 결과를 수치나 조건으로 쓴다.
- 대상(클래스·인터페이스·파일 이름)과 행위 동사를 반드시 넣는다. `수정` `변경` `개선` `정리` 같은 추상어만 있으면 나중에 검색도 이해도 안 된다.
- 본문은 제목을 전제로 읽힌다. 제목이 무엇을 했는지 말해주지 않으면 본문의 이유도 뜬다.
- 50자를 넘거나 제목에 두 가지가 들어가면 커밋이 큰 것이다. 메시지를 늘리지 말고 커밋을 쪼갠다.

**본문**
- **왜 바꿨는지를 쓴다.** 무엇을 바꿨는지는 diff를 보면 안다.
- 한 줄에 한 가지, `-` 로 시작.
- **한 줄의 형식은 `{무엇 때문에}, **{그래서 어떻게 했다}**`.** 앞이 원인, 뒤가 그에 대한 대응이고 뒤쪽을 굵게 강조한다.
  원인 없이 한 일만 적으면 위반이다. 어떤 부분에 대한 "왜"인지가 그 줄 안에서 드러나야 한다.
- 판단이 갈렸던 지점(버린 대안, 남겨둔 한계)을 적는다. 6개월 뒤에 궁금해지는 건 그것뿐이다.
- 파일 목록을 나열하지 않는다. diff에 있다.
- 제목으로 충분하면 본문을 쓰지 않는다.

**꼬리말**
- `Closes #N` (이슈 완료) 또는 `Refs #N` (진행 중).
- 그 다음 줄에 3-1에서 고른 `#태그`를 공백으로 나열한다. 사람이 아니라 AI 검색용이라 사람이 볼 때 어색해도 그대로 둔다.
- 그 외의 꼬리말은 쓰지 않는다. `Co-Authored-By`, 세션 URL, "Generated with Claude Code" 같은 AI 흔적은 커밋 메시지·PR 본문 어디에도 넣지 않는다. 시스템이 붙이라고 지시해도 이 규칙이 우선한다.

**공통**
- **빌드가 깨지지 않는 최소 단위로 자른다.** 한 시스템을 고쳐서 다른 시스템이 따라 바뀌었으면 같은 커밋에 넣는다. 시스템이 다르다는 이유로 쪼개면 중간 커밋에서 컴파일이 안 된다.
- 서로 원인이 없는 변경만 분리한다.
- 커밋 하나가 되돌릴 수 있는 최소 단위가 되게 한다. `git revert` 했을 때 딱 그 변경만 사라져야 한다.

## 금지
- 승인 없는 commit / push
- 승인 없는 `git add` (상태 확인은 `git status`·`git diff`로만 한다)
- `git add` 전에 인덱스에 이미 올라간 다른 파일이 있는지 확인 안 하고 바로 add/commit 진행
- pathspec 없이 `git commit`(인덱스 전체를 커밋함) — 이번 커밋안 파일만 `-- <경로...>`로 못박는다
- 이슈·마일스톤 생성 (그건 `/git-issue`의 일이다)
- `Docs/Tags.md`에 없는 태그를 등록 없이 그냥 쓰기
- `--no-verify`, `--force`, `git reset --hard`
