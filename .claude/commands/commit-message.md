# 1. diff 파일 읽기
- 사용자가 파일 경로를 전달하면 해당 파일을 읽는다.
- 전달하지 않으면 `.claude/git/diff/` 에서 가장 최근 파일을 읽는다.

# 2. 이슈 넘버 확인
- 각 fieldset에 해당하는 이슈 넘버가 있는지 사용자에게 묻는다.
- 없으면 제목에서 생략한다.

# 3. 커밋 메시지 작성
- fieldset 하나 = 커밋 하나
- diff 파일의 내용을 그대로 커밋 메시지 형식에 옮긴다

## 형식
```
타입(스코프): 제목 (#이슈넘버)

본문

꼬리말
```

- **타입**: fieldset 표의 `변경 타입` 값 사용
- **스코프**: 변경된 대상을 접미사로 명시 (`_cs` / `_md` / `_method` / `_system` / `_folder`). 없으면 `()`
- **제목**: 본문 요약, 한글, 50자 이내, 마침표 없음
- **본문**: fieldset `<details>`의 항목들을 그대로 옮김
- **꼬리말**: 관련 이슈 있으면 `Closes` / `Fixes` / `Ref` / `Related to`. 없으면 생략

# 4. 파일 저장
- 경로: `.claude/git/commit/`
- 파일명: 커밋 제목 (예: `file(Assets_folder)-폴더명공백제거.md`)
- fieldset이 여러 개면 커밋마다 파일 하나씩 생성

# 5. 피드백 / 커밋 선택
- 작성된 커밋 메시지를 채팅창에 출력한다.
- "피드백이 있으면 말씀해주세요. 이대로 커밋할까요?" 를 출력하고 대기한다.
- 수정 지시가 오면 파일 수정 후 `# 5` 반복
- 커밋 진행 의사를 밝히면 `# 6` 으로 이동

# 6. 커밋
- fieldset 순서대로 커밋을 하나씩 실행한다.
- 각 커밋마다:
  1. 해당 fieldset 표의 파일들만 `git add`
  2. 작성된 커밋 메시지로 `git commit`
- 모든 커밋 완료 후 결과를 채팅창에 출력한다.
