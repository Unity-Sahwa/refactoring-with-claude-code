## 0. 절차 (반드시 지킬 것)

1. 대상 `.cs` 파일을 Read로 전체를 컨텍스트에 가져와 평가한다.
2. 1절 축으로 평가한다. 근거를 파일:줄로 1건 이상 인용 못 하면 그 행은 `해당없음`으로 적는다.
3. 2절 형식의 판정표를 출력한다.
4. **코드를 수정하지 않는다. 보고만 한다. 파일도 만들지 않는다.**

- 네이밍·서식 위반은 여기서 다루지 않는다 (`code-convention` 담당).
- 주석 위반은 여기서 다루지 않는다 (`comment-convention` 담당).
- `Old/`, `_Test`, `PerformanceTest`는 제외한다.

## 1. 평가 축

### 1-1. 변경 파급 (이거 하나 고치면 몇 군데가 깨지나)
| 핵심 질문 | 좋음 | 나쁨 (=찾는 냄새) |
|---|---|---|
| 의존을 밖에서 받나, 안에서 직접 만드나 | 주입으로 받음 | 본문에 `new`·`Find`·`GetComponent`·싱글톤 직접 호출 |
| 남의 내부까지 파고드나 | 1단계까지만 체이닝 | 1단계 초과하는 체이닝 |
| 공통 값은 SO에, 개체별 값은 SerializeField에 있나 | 공통 값 SO / 개체별 값 `[SerializeField]` | 공통 값이 매직넘버나 `[SerializeField]`에 흩어짐, 또는 개체별 값이 SO에 있어 다 같이 바뀜 |

### 1-2. 이해 비용 (처음 보는 사람이 30초에 흐름을 따라가나)
| 핵심 질문 | 좋음 | 나쁨 (=찾는 냄새) |
|---|---|---|
| 흐름 설명에 "그리고/또"가 1개 이하인가 | 접속사 1개 이하 | 접속사 2개 이상(책임 분산) |
| 메서드 본문이 15줄 이하인가 | 15줄 이하 | 16줄 이상 |
| 인자 수가 적나 | 3개 이하 | 4개 이상 |
| bool 인자 값에 따라 한 메서드가 다른 일을 하나 | 일마다 메서드 따로(`GetAngleInDegrees()`·`GetAngleInRadians()`) | `GetAngle(bool inDegrees)`처럼 안에서 `if(bool)`로 갈라짐 |
| `var` 선언의 오른쪽에서 타입이 바로 보이나 | `new 타입()`·캐스팅·리터럴 (`var x = new Player()`) | 메서드 반환값을 `var`로 받음 (`var data = LoadData()`) |

### 1-3. 교체/삭제 용이 (기능 하나 빼거나 갈아끼울 때 깔끔히 떨어지나)

| 핵심 질문 | 좋음 | 나쁨 (=찾는 냄새) |
|---|---|---|
| `[Inject]` 필드 타입이 인터페이스·추상 클래스인가 | 인터페이스·추상 클래스 | 구체 클래스 |
| enum·dictionary·list 요소가 늘면 그걸 쓰는 메서드도 고쳐야 하나 | 요소가 늘어도 메서드는 그대로 | 늘 때마다 그 메서드(`switch`/`if`, 인덱스, `new` 호출 등)를 고쳐야 함 |
| 필수 의존(`[Inject]`)에 방어 코드가 붙어있나 | 없음(예외로 드러남) | null 체크로 막혀 조용히 넘어감 |
| 선택 의존(`[Inject(true)]`)이 없을 때 경고 남기고 그 기능만 건너뛰나 | 경고 로그 + 그 기능만 건너뜀 | 경고 없이 조용히 넘어가거나 전체가 멈춤 |

### 1-4. 과설계 없음 (YAGNI — 안 쓰는 걸 미리 만들지 않았나)
| 핵심 질문 | 좋음 | 나쁨 (=찾는 냄새) |
|---|---|---|
| 정의만 있고 어디서도 안 부르는 메서드·필드가 있나 | 전부 이 파일이나 다른 파일에서 호출됨 | 호출처 검색 결과 0건인 `public`·`private` 메서드·필드 있음 |
| 이 클래스명·구현 인터페이스명을 다른 파일에서 검색하면 나오나 | 다른 파일에서도 나옴(실제 쓰임 있음) | 이 파일 말고는 안 나옴(구현 1개뿐인 인터페이스, 호출 1곳뿐인 레이어) |

### 1-5. 유니티 함정 (엔진 특성상 유지보수를 터뜨리는 지점 — 해당될 때만)
| 핵심 질문 | 좋음 | 나쁨 (=찾는 냄새) |
|---|---|---|
| 구독·해제 짝이 맞나 | `OnEnable`-`OnDisable` 짝, 또는 `Awake`-`OnDestroy` 짝 | 짝이 안 맞음(해제 없음, 또는 `Awake` 구독인데 `OnDisable`에서 해제하는 식으로 레벨이 섞임) |
| 코루틴·async가 파괴/전환 시 Stop/Cancel로 정리되나 | StopCoroutine·CancellationToken 있음 | 없이 계속 돎 |
| 코루틴·async 취소·중단 시 예외를 삼키지 않고 드러내나 | catch에서 로그 남기거나 그대로 던짐 | 빈 catch로 조용히 삼킴 |
| static 필드에 중복 처리·삭제 처리 로직이 있나 | 중복 처리(`Instance`가 이미 있으면 파괴 또는 덮어쓰기) + 삭제 처리(`OnDestroy`에서 null) 둘 다 있음 | 둘 중 하나라도 없음 |
| 유니티 오브젝트 타입 변수에 참조만 보는 문법을 쓰나 | `== null`/`!= null`만 씀 | `?.`·`??`·`??=`·`is null`·`case null`·`ReferenceEquals`·`(object)` 캐스팅 비교 |
| 인터페이스 타입 변수의 null 검사를 `(_x as UnityEngine.Object) == null`로 하나 | 그렇게 함 | `== null`·`is null`·`?.`로 바로 비교 |
| 밖에서 파괴될 수 있는 유니티 오브젝트 참조를 파괴 시 null 처리하거나 쓸 때 `== null` 검사하나 | 둘 중 하나 있음 | 둘 다 없음 |
| 매번 만들 수 있는 걸 한 번만 만들어 캐싱하나 | `WaitForSeconds`·`StringToHash`·`GetComponent` 결과를 필드에 저장 | 호출 때마다 `new WaitForSeconds`·문자열 해시·`GetComponent` |
| `Update`·`FixedUpdate`·`LateUpdate`·코루틴 루프 안에 무거운 호출이 있나 | 없음 | `GetComponent`·`Find`·`Camera.main`·LINQ·문자열 합치기·`new` |
| 메서드·애니메이터 파라미터 이름을 문자열로 넘기나 | 직접 호출·`nameof`·해시 | `Invoke("이름")`·`SendMessage`·`StartCoroutine("이름")`·`SetTrigger("문자열")` |

> `?.`·`??`·`is null` 등은 C# 문법이라 유니티가 오버로드한 `== null`(파괴 감지)을 타지 않는다.
> 인터페이스 타입은 컴파일 시점에 유니티 `==` 오버로드가 안 붙어 파괴 감지를 못 한다. 순수 C# 구현체가 생기면 도우미 메서드로 바꾼다.
> 단 `OnDied?.Invoke()` 같은 순수 C# event·객체에는 `?.`를 써도 된다.

## 2. 판정표 출력

1절의 모든 질문을 하나도 빠뜨리지 않고 옮긴다.

| 판정 | 축 | 질문 | 근거 (파일:줄) |
|---|---|---|---|
| FAIL | 1-1 | 의존을 밖에서 받나 | PlayerMove.cs:22 — `FindObjectOfType<AudioPlayer>()` 직접 호출 |
| 해당없음 | 1-5 | 코루틴 정리 | 코루틴 없음 |

- 판정은 `PASS` / `FAIL` / `해당없음` 셋 중 하나.
- `FAIL`에는 반드시 파일:줄 근거를 적는다. 근거 없으면 적지 않는다.

그 아래에 **문제와 개선 방향**을 적는다.
- 좋은 점, 강화하면 좋은 방향을 적는다.
- **문제·단점·약점을 구체적으로** 적는다.
- 문제는 항상 개선 방법과 함께 적는다.
