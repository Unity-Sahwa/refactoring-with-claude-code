# 관계도 HTML 작성 규칙

> 대상: `Docs/SystemMap.html` 같은 단일 파일 관계도(노드 = 네모, 화살표 = 의존).
> 목적: 매번 시행착오로 다시 그리지 않기 위해, 확정된 배치·경로 규칙을 고정한다.

## 0. 원칙

- **좌표를 손으로 찍지 않는다.** 데이터(노드·엣지)만 적고, 자리와 선은 코드가 계산한다.
- **한 파일로 끝낸다.** 빌드 없이 브라우저로 바로 열린다. 외부 스크립트 의존 없음.
- **눈으로 보기 전에 숫자로 검증한다.** 관통·겹침·교차 수를 세는 노드 스크립트를 돌린다.

## 1. 파일 구조

| 순서 | 내용 |
| --- | --- |
| 1 | `<style>` — 색 토큰(`:root`), 다크 모드 대응 |
| 2 | 헤더 · 범례 · `<svg class="map">` · 우측 상세 패널 |
| 3 | `<script>` 안 IIFE — 데이터 → 배치 → 경로 → DOM |

스크립트 안 순서도 고정한다.
`NODES` / `EDGES` → 인접 목록(`outs`, `ins`) → 자리 → 상수(`NW` 등) → SVG 헬퍼 → 경로 → 노드 → 상호작용.

## 2. 데이터

- `NODES`: `{ id, name }`만. 좌표 금지.
- `EDGES`: `{ s, t, v, k }` — `v`는 **왜 필요한지**, `k`는 **어떤 타입으로 주고받는지**. 클래스를 직접 잡았으면 `cls: 1`.
- 양쪽에 서로를 향하는 엣지가 있으면 그때만 `back`(서로 씀)으로 본다. 위상 정렬로 추정하지 않는다.

## 3. 자리 (배치)

- 격자에만 놓는다. `x = PADL + col * COLW`, `y = PADT + row * STEPH`. 행마다 가운데 정렬 같은 건 하지 않는다.
- 테두리를 돌며 자리를 잡고 가운데는 비운다(허브 노드가 있으면 그 자리).
- 초기 배치 후 **두 칸씩 맞바꿔 보며 비용이 줄면 채택**한다. 비용 = 행·열 거리 + 꺾임 1점 + 우회해야 하면 4점.
- 끝나면 빈 행·열을 당겨 압축한다(`compact`). 캔버스 크기는 압축 후 값으로 정한다.
- 세로 간격은 박스 높이의 3배 이상 둔다(우회 선이 지나갈 여백).

## 4. 경로 (핵심)

경로는 **두 벌**을 만들어 둔다.

| | 언제 | 규칙 |
| --- | --- | --- |
| 격자 경로 | 전체 보기 | **어떤 박스도 지나지 않는다** |
| 직행 경로 | 하나를 고르거나 마우스를 올렸을 때 | 흐려진 박스는 가로질러도 되고, **진하게 남은 박스는 피한다** |

격자 경로 규칙:

1. 사이가 비어 있으면 직선, 한 번 꺾는 ㄱ자까지만 쓴다.
2. 막혀 있으면 **행 사이 여백**으로 가로 이동하고 **열 사이 통로**로 세로 이동한다. 박스 위는 절대 안 지난다.
3. 여백·통로 안에서는 이미 깔린 선과 구간이 겹치지 않는 칸을 골라 깐다(선착순, 다 차면 마지막 칸 공유).
4. 여백의 위아래 끝에서 `STUB`만큼 떼고 그 안쪽에만 깐다. 안 그러면 박스 코앞에서 급하게 꺾인다.

직행 경로 규칙:

1. 두 면의 높이(또는 좌우 폭)가 겹치면 그 안에서 값을 맞춰 **직선**으로 만든다.
2. 안 되면 면에서 `STUB`만큼 곧게 빠져나온 뒤 한 번 꺾는다.
3. 다 막히면 격자 경로를 그대로 쓴다.

## 5. 출입 면

- 상하좌우 네 면 다 쓴다. 방향에 맞는 면을 고른다.
- 한 면을 여러 선이 쓰면 **상대 노드의 행·열 순으로 줄을 세워** 자리를 나눈다. 도착 순서가 뒤바뀌면 그 앞에서 선이 꼬인다.
- 박스에 꽂히기 직전 **`STUB`(= 박스 높이)만큼은 반드시 곧게** 들어온다.
- 선택·호버 상태에서는 **같은 색끼리는 겹쳐도 된다**(방향이 같으니 정보 손실 없음). 색이 다르면 자리를 나눈다.
- 길이 0짜리 마디는 버린다. 남겨 두면 `marker-end`가 엉뚱한 방향을 본다.

## 6. 그리는 순서와 상호작용

- `<g>` 순서는 **노드 먼저, 선 나중**. 흐려진 박스 위로 선이 지나갈 때 선이 위에 보여야 한다.
- 상태는 `sel`(클릭)과 `hov`(마우스)를 따로 두고 `view = sel || hov`로 그린다. 상세 패널은 `sel`만 따른다.
- `Esc`와 "전체 보기" 칩으로 해제한다.

## 7. 검증 (그린 뒤 반드시)

노드로 스크립트를 로드해 SVG DOM을 흉내 내고, 만들어진 `path`와 `rect`를 직접 센다.

- **박스 관통 = 0** (전체 보기 기준. `Esc` 핸들러를 호출해 선택을 푼 뒤 센다)
- **선 겹침**(같은 축·같은 좌표에서 구간이 포개짐) — 0에 가깝게
- **선 교차** — 이전 값보다 줄었는지만 본다. 0은 목표가 아니다.

세 값을 고치기 전후로 같이 보고한다. 겹침을 줄이려다 교차가 크게 늘면 되돌린다.

## 8. 하지 말 것

- 좌표 하드코딩, 특정 노드만 예외 처리
- 의미 없는 축(단계·깊이·등급)을 자리에 부여하고 그걸 설명으로 붙이기
- 화살표를 곡선·라운드로 만들기(직교 직각으로 통일)
- 검증 없이 "깔끔해졌다"고 보고하기
