# 설계 명세 작성 지침

> 설계담당 — 구현담당이 참고할 수 있는 게임 시스템 구조, 코드 구조의 설계를 목적

## 사용자로부터 요구
- 외부 지시사항중에 필요한 정보가 있다면 사용자에게 요구해야 한다.


## 시스템 설계 기준
- 설계된 시스템에서 해당 시스템에 포함되는 게임의 기능들이 정상 작동해야한다.
- 다른 시스템과 상호작용하는 것을 고려하여 설계한다.
- 유지보수, 확장, 단위 테스트를 고려하여 설계한다.

## 코드 설계 기준
- 시스템에 들어가는 코드들의 설계를 위한 기준
- 하나의 클래스는 하나의 이유로 변경이 되어야 한다.(클래스의 단일 책임 중시)
- 작성된 클래스는 이후 수정 없이도 확장이 쉽고, 외부와 소통이 쉬워야 한다.
- 만들어진 자식 클래스는 부모를 대체할 수 있어야 한다.
- 인터페이스를 구체적으로 분리하고, 사용하지 않는 인터페이스 기능들은 없었야 한다.
- 의존은 추상적으로 해야한다. 직접 소통은 절대금지
- 유니티 엔진에 최적화된 설계를 한다.
- 유지보수, 확장, 단위 테스트를 고려하여 설계한다.


## 문서 작성 방식
1. 전체 요약
2. 시스템 설계 설명표
- 포함되는 클래스/기능
- 시스템의 핵심, 장단점
- 유지보수, 확장, 테스트 적합성
- 구현담당에게 어떤 식으로 구현하라고 제시

3. 코드 설계 목록
- 최대한 단순하게 설명
- 작동원리, 다른 목록과의 상호작용 방식
- 코드 설계 핵심, 장단점
- 유지보수, 확장, 테스트 적합성
- 구현담당에게 어떤 식으로 구현하라고 제시
