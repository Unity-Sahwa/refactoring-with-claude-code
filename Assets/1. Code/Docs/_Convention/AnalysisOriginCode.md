# 원본 코드 분석 지침

> 분석담당 — 원본 코드 분석 시 적용

## 매우 중요
- 이전 결정을 참고하여 임의로 판단하지 말 것.
- 임의로 판단하지 말 것.

## 분석기준
- 유지보수가 되는지
- SOLID 원칙에 위배되는지
- 객체지향적으로 구현됬는지
- 설계, 구현 단계에서 처리되는 문제는 생략(단순버그, 오탈자, 코드컨벤션, 주석, #region, 중복작성 등)
- Unity Engine에 최적화되어 있는지

## 작성방식
- 철저히 코드 위주로 문제 분석 및 작성
- 문제 항목 헤더: `### [카테고리] 제목` 형식 (예: `### [버그]`, `### [결합도]`, [SOLID-SRP])
- 코드 블록을 먼저, 설명은 코드 아래 2~3줄 이내
- 나열 리스트(1. 2. 3.) 금지 — 설명은 짧은 문장으로
- 기능 목록 표 형식: `기능 | 진입 메서드 | 비고`
- 문제 요약표 형식: `구분 | 문제 | 심각도` (3열)

## 작성 목록
- 기존 기능 목록 (리팩토링 후 반드시 유지되어야 할 동작)
- 문제 분석
- 문제 요약표
