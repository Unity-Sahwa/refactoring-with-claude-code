# 인사이트 수집 규칙

## 목적
리팩토링 과정에서 개발자가 느낀 경험·판단·아이디어를 기록한다.
기술 문서(분석/설계/피드백)에 남지 않는 주관적 인사이트를 포트폴리오 재료로 축적한다.

---

## 언제
작업 완료 후, 다음 담당자에게 인수인계하기 직전.

---

## 질문 생성 방법

에이전트는 자신이 수행한 작업을 돌아보며 아래 항목에 해당하는 것들을 추출한다.
해당 항목이 없으면 질문도 없다. 많을수록 질문도 많아진다.

| 추출 항목 | 질문 방향 |
|-----------|-----------|
| 예상과 달랐던 발견 | "~를 분석하면서 예상과 달랐던 부분이 있었나요?" |
| 여러 선택지 중 내린 결정 | "~와 ~ 중 ~를 선택했는데, 이 결정이 맞다고 느끼시나요?" |
| 발견한 문제점 | "~라는 문제를 발견했는데, 이게 얼마나 중요하다고 느끼셨나요?" |
| 개선 아이디어 | "~라는 개선 방향이 나왔는데, 우선순위를 어떻게 보시나요?" |
| 흥미롭거나 인상 깊었던 점 | "~를 작업하면서 어떤 점이 가장 인상 깊으셨나요?" |
| 아쉬웠던 점 | "이번 작업에서 다르게 했으면 좋았을 부분이 있다면요?" |

질문은 구체적으로 — 작업 내용을 직접 언급하며 물어볼 것.
"어떠셨나요?" 같은 막연한 질문은 금지.

---

## 응답 저장 규칙

### 파일명
```
6-portfolio/YYYY-MM-DD-[파트명]-[담당자].md
```
예시:
```
6-portfolio/2026-04-02-core-infrastructure-analyzer.md
6-portfolio/2026-04-02-core-infrastructure-tester.md
```

### 파일 형식
```markdown
# [파트명] — [담당자] 인사이트
> 날짜: YYYY-MM-DD
> 담당: [역할명]
> 관련 작업: [작업 내용 한 줄 요약]

---

## Q. [질문 내용]
[사용자 응답]

## Q. [질문 내용]
[사용자 응답]
```

### 저장 시점
사용자가 모든 질문에 응답한 후 한 번에 저장.
응답이 없거나 "없음"인 경우 해당 항목은 저장하지 않음.

---

## 에이전트 행동 순서

1. 작업 완료
2. 작업을 돌아보며 인사이트 추출 항목 탐색
3. 추출된 항목 기반으로 질문 생성 및 사용자에게 질문
4. 응답 수집 → `6-portfolio/`에 저장
5. 인수인계 절차 진행
