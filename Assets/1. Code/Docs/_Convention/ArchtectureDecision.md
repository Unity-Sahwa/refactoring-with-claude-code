# Architecture Decision Records(ADR)
## 왜 쓰는가
- 아키텍쳐 결정을 템플릿에 맞게 기록.(아키텍쳐는 시스템의 구조 설계, 코드 설계를 포함)
- "이 코드는 왜 이렇게 설계되었는가?"를 기록
- 미래의 나, 팀원이 ADR을 보고 프로젝트 전체 흐름을 이해하기 위함.
- 기술부채가 쌓이는 것을 방지하기 위함

---

## 언제 쓰는가
아래 질문 중 하나라도 해당되면 ADR 작성 대상이다.

- 두 가지 이상의 선택지를 고민했는가?
- 나중에 "왜 이렇게 했지?" 라고 의아해할 것 같은가?
- 기존 패턴을 의도적으로 어겼는가?
- 성능/유지보수/확장성 중 하나를 희생해서 다른 것을 얻었는가?
- 코드 설계의 변경이 있었는가?

## 파일 규칙

6-architecture-decision-records/
├── ADR_CONVENTIONS.md          ← 지금 이 문서
└── ADR-NNN-짧은-제목.md        ← 개별 결정 기록

- NNN: 001부터 순서대로
- 제목: 소문자, 하이픈 구분, 한글 가능 (ex: `ADR-001-singleton-to-di.md`)
- 한 파일 = 한 결정
