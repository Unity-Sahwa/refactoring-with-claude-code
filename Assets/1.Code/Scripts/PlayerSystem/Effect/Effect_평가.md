## 2. 문제와 개선 방향

**좋은 점:** Hitbox와 같은 견고한 풀링·구독·코루틴 정리. 데이터로 이펙트 추가(코드 무수정). 풀 고갈 경고 추가로 무성한 누락 방지.

**문제 / 처리 결과:**

1. **[검토/보류] Effect ↔ Hitbox 트윈 구조** — `PlayerEffectHandler`≈`PlayerHitboxHandler`, `EffectProvider`≈`HitboxProvider`. 차이: Hitbox는 전투값 `Setup` 단계 추가 + 풀 크기 1(켜진 동안만), Effect는 풀 크기 3(상태 종료 후에도 잔존하도록 설계)이라 **동작이 실제로 다름**.
   - 결정: 구현이 둘뿐 + 동작 차이 + rule-of-three 고려해 **지금 추출 안 함(보류).** 세 번째 유사 시스템(적 히트박스 등)이 나오면 그때 공용 풀/스폰 골격 추출 판단.
   - 주의: 둘이 트윈이므로 한쪽 버그 수정 시 다른 쪽도 확인할 것(예: 본 평가의 엣지들이 양쪽 동일했음).

2. **[해결] 풀 고갈 경고** — `EffectProvider.Rent`에서 "키는 있는데 큐가 빔 = 고갈"일 때만 `Debug.LogWarning`, "키 없음 = 로딩 전"은 무경고로 분리. 동시 다발 이펙트가 풀(3개)을 넘으면 인지 가능.

3. **[해당없음] 로딩 중 Provider 파괴 엣지** — 단일 게임플레이 씬 + 영속 Provider라 로딩 윈도우 중 파괴가 도달 불가. 가드 불필요(YAGNI)로 결론.

## 3. 결론

Effect 자체 나쁨 0. #1은 Hitbox와의 트윈 관계로 "보류" 기록(3번째 등장 시 추출 재검토).
