# 렌더링 최적화 기록

- 작성일: 2026-08-25
- 범위: Shader Warmup / Material Duplicate Finder

## 1. 첫 등장 오브젝트 셰이더 팝인

### 기존 방식
씬 시작 시 카메라로 맵 전체를 한 번 비추고, 이펙트 오브젝트도 미리 껐다 켜서 렌더링을 강제로 트리거.

### 문제
- 화면에 노출되지 않은 각도·거리의 variant는 여전히 누락됨
- 풀링으로 나중에 생성되는 오브젝트, 씬에 미배치된 프리팹은 커버 불가
- 맵 전체 스캔에 로딩 시간·연산 비용 소모
- 씬 구성이 바뀔 때마다 스캔 범위를 다시 맞춰야 함

### 원인 분석
Unity는 셰이더 keyword 조합(variant)을 최초 렌더링 시점에 동적으로 컴파일함. 이 컴파일이 메인스레드를 블로킹해 스터터로 나타남.

카메라 스캔 방식은 "화면에 보였는가"를 기준으로 삼는데, 정작 필요한 건 "어떤 shader+keyword 조합이 쓰였는가"임. 기준 자체가 어긋나 있었음.

### 개선
`ShaderVariantCollection`으로 실제 사용된 조합만 기록하고, 로딩 구간에서 `WarmUp()`으로 일괄 미리 컴파일.

- Recording 중 프리팹/풀 오브젝트를 한 번씩 노출시키면 함께 수집됨
- 수집 대상이 "화면 노출"이 아닌 "실제 variant"라 스캔 범위·정확도 문제가 사라짐
- 결과물은 씬과 무관한 독립 에셋(.shadervariants) — 앱 실행 중 1회 WarmUp이면 이후 재사용됨

### 결과
실측은 적용 후 프로파일러로 확인 필요.

| 항목 | 카메라 스캔 | Variant Collection |
|---|---|---|
| 커버리지 | 노출된 것만 | 실사용 variant 전체 |
| 풀링/프리팹 | 미커버 | recording 중 노출 시 커버 |
| 유지보수 | 씬 바뀔 때마다 수동 조정 | 재녹화로 자동 갱신 |
| 적용 상태 | — | 설정 대기 |

## 2. 중복 머티리얼로 인한 배칭 손실

### 기존 방식
별도 검사 도구 없이, 작업자가 씬을 직접 돌아다니며 눈으로 머티리얼 사용 현황을 확인.

### 문제
- 육안 확인은 값이 미세하게만 다른 복제본을 놓치기 쉬움
- 씬 규모가 커질수록 전수 확인 자체가 비현실적
- 불필요한 복제 머티리얼이 방치되어 메모리·드로우콜 낭비가 누적됨

### 원인 분석
SRP Batcher/GPU Instancing은 동일 머티리얼 에셋일 때만 배칭함. 값이 완전히 같아도 에셋이 복제되어 있으면 별개 머티리얼로 취급되어 배칭이 깨짐.

즉 판단 기준은 "이름이 비슷한가"가 아니라 "`shader` + 모든 프로퍼티값이 동일한가"임.

### 개선
에디터 스크립트로 씬 내 모든 `Renderer`의 머티리얼을 수집하고, `shader + 프로퍼티값` 시그니처가 같은 것끼리 그룹핑해 중복을 콘솔에 출력.

```
Tools > 씬 머티리얼 중복 검사

[MaterialDuplicateFinder] 중복 그룹 N개 발견
- 셰이더: Universal Render Pipeline/Lit
    Assets/.../Rock_01.mat
    Assets/.../Rock_01_copy.mat
```

구현: `MaterialDuplicateFinder.cs` (같은 폴더)

### 결과
중복 식별 자체는 즉시 가능. 실제 드로우콜 감소는 찾아낸 중복을 하나로 합친 뒤 확인 필요.

> 다음 단계: 도구 실행 → 출력된 그룹별로 하나만 남기고 참조 교체 → Frame Debugger로 배칭 변화 확인

---

두 항목 모두 "씬을 직접 뒤지는 대신 Unity가 이미 알고 있는 데이터를 그대로 쓴다"는 동일한 방향의 개선. 결과 수치는 실제 적용 후 채워 넣을 것.
