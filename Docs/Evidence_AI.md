**주제: AI를 도구가 아니라 관리 대상으로 다루기.** 속도가 아니라 통제와 판정 기준이 결과를 갈랐음.

## 활용 방식
- 코드 작성을 AI가 맡고, 사람은 설계 결정·검수·흐름 파악을 담당
- 규칙을 한 번에 확정하지 못하고 여러 차례 수정·간소화하며 다듬음 (커밋 이력에 남아 있음)
- 규칙은 처음부터 전부 설계하려 하면 끝이 없음. 모르는 것을 모르기 때문.
  대신 만들다 막히는 지점에서 기존 규칙과 결이 다르면 새 항목으로 보고 쌓아가는 방식을 택함

## 실제로 겪은 문제 (사건 기록)
| 문제 | 대응 |
|---|---|
| 대화가 끝난 뒤 허락 없이 파일을 수정 | 파일 생성·삭제·변경 전 질문 규칙을 `CLAUDE.md`에 명시 |
| 사용자인 척 스스로에게 질문을 만들고 거기에 답함 | `"user"`가 붙은 메시지를 최우선 무시 규칙으로 등록 |
| 이미 작성해 둔 규칙을 어김 | 규칙을 커맨드로 분리해 호출 시점에 다시 읽게 함 |
| 이미 설계해 둔 시스템을 쓰지 않고 `SerializeField`·`public`으로 직접 참조 | `system-usage` 규칙 작성 |
| 매 프레임 도는 `Update`에 비용 큰 작업을 넣음 | 코드 평가 규칙에 항목 추가 |
| 씬 전체를 훑는 `Find` 계열 사용 | 동상 |

롤백까지 간 사례는 없음. 누락·맥락 오해로 인한 실수는 에러 코드를 넘겨주면 스스로 해결함.

### 자문자답 문제 — 발견부터 감지 자동화까지
AI가 응답을 끝내지 않고, 오지도 않은 사용자 발화(`user`로 시작하는 줄)를 스스로 지어내 이어 쓰는 문제를 발견함. 대응 과정:
1. 세션 로그(`~/.claude/projects/*/*.jsonl`)를 전수 조사해 실제 발생 규모 확인 — 2026-08-21~09-09, 20일간 35건
2. 정규식(`(?m)^[ \t]*user`)으로 누출 지점을 감지하는 PowerShell 훅 작성, `Stop`·`PreToolUse` 이벤트에 연결해 이어진 도구 실행을 차단
3. 감지 시 사례를 로그로 남기고, 날짜·세션·시간순으로 정리한 리포트 작성 (`Docs/SelfAnsweredTurns.html`)

근거: `.claude/hooks/self-turn-guard.ps1`, `Docs/SelfAnsweredTurns.html`

## AI가 만든 결과를 버린 기록
통제는 말로 되지만 폐기는 증거가 남음. 납득하지 못한 것은 남기지 않았음.
- 상속 + 제네릭 상태 구조: 만들다 보니 제네릭에 플레이어 전용 타입이 들어가 플레이어 상태머신으로 고정됨.
  상속으로 만든 목적이 사라져 폐기 (`Evidence_Player.md` 참고)
- Unity Localization + Addressable: 도입 후 필요 없다고 판단해 제거, 자체 구현으로 전환
- 코드 설계 에이전트: 만들었다가 재구현하고 결국 커맨드 방식으로 정리
- git-flow·PR 규칙 문서: 실효가 없어 삭제
- 전면 자동화(코드 작성 → 평가 → 요약): Pro 요금제 토큰이 곧바로 바닥나고 결과 만족도가 낮아 포기.
  부분 자동화도 하지 않기로 함

## 심각하다고 본 지점
- **책임감 저하** — AI에 다 맡기고 결과물이 많아지면 "그대로 진행"으로 떠맡기게 됨
- **기반 지식 공부 태만** — AI로 되는 게 많아질수록 기초를 안 보게 됨
- **보편적 답의 한계** — AI는 웹에서 보편적으로 쓰이는 방식을 따름. 뾰족한 해법은 사용자가 힌트를 줘야 나옴.
  그런데 현재 사용자는 게임 개발 초보라 AI가 더 잘함. 그럼 사용자가 할 일은
  ① AI가 만든 것에 항상 의문을 제기하고 ② AI가 답을 도출하는 방식을 알아 미리 대비하는 것
- **규모의 문제** — AI가 없던 시절에도 초보 프로그래머가 게임을 돌아가게는 만들었음.
  고급으로 가는 조건은 제대로 분리되고, 고치기 쉽고, 보기 쉬워서 규모가 커져도 감당되는 것.
  AI는 그 규모를 더 빨리 키우므로 이 조건이 더 중요해짐

## 필요하다고 본 것
- **환각 대응** — 환각이 심각한 문제로 번지기 전에 걸러낼 장치
- **권한 제한** — 코드 변경은 눈에 띄지만 설정 변경·내부 변경은 조용히 지나감. 그래서 권한을 빡빡하게 걸어야 함
- **양방향 번역 규칙** — AI에게 줄 때는 해당 분야에 맞는 설명을 자세히, 받을 때는 이해하기 쉬운 형태로.
  여기에 사용자의 어휘력·표현력이 필요함
- **AI를 위한 기록** — 커밋은 사람을 위한 기록임. AI가 제대로 작업하려면 별도의 기록이 필요함
