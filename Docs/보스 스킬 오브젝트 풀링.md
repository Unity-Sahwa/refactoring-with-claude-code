# 보스(위수) 스킬 프리팹 오브젝트 풀링 작업 기록

작성일: 2026-08-31
대상: `Assets/1.Code/Scripts/EnemySystem/Boss/`

---

## 1. 작업 배경

보스 스킬 프리팹이 패턴 실행 시점마다 `Instantiate`되고 수명이 다하면 `Destroy`되는 구조였다.
첫 등장 시 셰이더/머티리얼 로딩으로 스터터가 발생하고, 전투 중 생성·파괴가 반복된다.

프리로드(카메라 앞에서 한 프레임 렌더해 셰이더를 워밍업하는 방식)는 이미 프로젝트에 있었다.
- `IPreloadTargetProvider` (`GimmickSystem/IPreloadTargetProvider.cs`) — 미리 렌더할 오브젝트 목록을 넘기는 인터페이스
- `EventPreloadRender` (`GimmickSystem/EventPreloadRender.cs`) — 등록된 provider들의 대상을 모아 전용 카메라로 한 번 렌더
- `PlayerEffectProvider` — 이미 같은 방식으로 풀 + 프리로드를 구현해 둔 선례

보스 스킬도 같은 구조에 태우기로 했다.

## 2. 확정한 프리팹 종류

`WisuMainRe`의 인스펙터에 프리팹 슬롯이 34개 있었으나, 실제 프리팹은 6종이었다.
`A1`, `B2` 등은 패턴 이름이고 `area1`, `area2` 등은 위치 구분이라, 같은 프리팹이 여러 슬롯에 중복으로 물려 있었다.

| skill | 프리팹 |
|---|---|
| A1 | Fire Bolt (move) |
| A2 | Fire Thrower (move) mk2 |
| A3 | Fire thrower (Stay) |
| B1 | Fire thrower (Stay) B1 |
| B2 | Fire thrower (Stay) B2 |
| B3 | Fire thrower (Stay) B3 |

이와 별개로 `dangerZone_Bolt` / `dangerZone_SmallPillar` / `dangerZone_LargePillar` / `dangerZone_B1` 4종은 이번 작업 범위에서 제외했다(여전히 `Instantiate` 사용).

## 3. 추가한 파일

### `WisuSkillPool.cs` (신규)

- `enum WisuSkill { A1, A2, A3, B1, B2, B3 }`
- `Entry { WisuSkill skill; GameObject prefab; int count; float lifeTime; }` 리스트를 인스펙터에 노출
- `Awake()`에서 `count`만큼 미리 `Instantiate` + `SetActive(false)`
- `IPreloadTargetProvider` 구현 — 만들어 둔 인스턴스를 `PreloadTargets`로 그대로 넘긴다

공개 API:

| 메서드 | 설명 |
|---|---|
| `Prefab(skill)` | 원본 프리팹 참조 (스케일·속도 등 프리팹 값을 읽을 때 사용) |
| `Get(skill, position)` | 대여. 수명은 해당 entry의 `lifeTime` |
| `Get(skill, position, lifeTime)` | 대여. 수명을 호출부가 지정 |
| `Return(instance)` | 반납. 비활성화 후 큐로 복귀 |

동작 세부:
- 대여 시 `ReturnAfter` 코루틴을 걸어 `lifeTime` 뒤 자동 반납한다. 코루틴 핸들은 `returnRoutines`에 보관해 수동 반납 시 중지한다.
- 회전은 항상 원본 프리팹의 회전을 적용한다(기존 호출부가 모두 그렇게 하고 있었다).
- 큐가 비면 그 자리에서 추가 생성한다. 이 인스턴스는 프리로드 렌더를 거치지 않으므로 스터터가 날 수 있다. `count`를 넉넉히 잡는 게 낫다.
- **큐는 skill이 아니라 prefab 참조를 키로 잡는다.** 같은 프리팹을 쓰는 skill끼리 인스턴스를 공유하고, `count`는 합산된다. `lifeTime`은 entry별로 남으므로 skill마다 다르게 줄 수 있다.

## 4. 수정한 파일

### `WisuMainRe.cs`
- `Pattern_A1.A1_prefabs`, `Pattern_A2.A2_prefabs`, `Pattern_A3/B1/B2/B3`의 `*_area*_prefab` 필드 전부 삭제 (총 34개 슬롯 → 0)
- `public WisuSkillPool skillPool;` 필드 추가. 인스펙터에서 씬의 풀 오브젝트를 연결한다.

### 패턴 스크립트 6종
- `Instantiate(prefab, ...)` → `wisu.skillPool.Get(WisuSkill.XX, position)`
- 스케일 계산에 쓰던 `prefab.transform.localScale.x` → `wisu.skillPool.Prefab(skill).transform.localScale.x`
- `ExecuteAreaPattern(...)`의 마지막 인자 `GameObject pillar` → `WisuSkill skill` (A3, B1, B2, B3)

A1/A2는 원래 `Mathf.Min(points.Count, prefabs.Count)`로 발사 개수를 정했다.
프리팹 리스트가 사라졌으므로 **points 개수를 그대로 발사 개수로** 사용한다.

A1은 추가로 순서를 바꿨다. 원래는 `Instantiate` 후에 `destroyTime`을 대입했는데,
지금은 대여 시점에 수명을 넘겨야 하므로 비행시간을 먼저 계산한다.
`speed`는 프리팹의 `FireBolt` 컴포넌트에서 읽는다. 이 비행시간이 곧 반납 시점이자 위험 표시(`DangerZone.scalingTime`)다.

### `FireBolt.cs`
- `Destroy(gameObject, lifeTime)` 삭제 → 수명은 풀이 관리
- `lifeTime`, `destroyTime`, `rb` 필드 삭제 (`rb`는 어디서도 읽지 않았다)
- `Start()` 삭제 (내용이 `rb` 대입뿐이었다)
- `OnTriggerEnter`에 `currentCharacterProvider == null` 가드 추가

### `FirePillar.cs`
- `Destroy(gameObject, lifeTime)` 삭제, `lifeTime` 필드 삭제
- **`Start()`의 초기화 내용을 `Init()`으로 이동.** 풀 인스턴스는 재사용 시 `Start`가 다시 돌지 않으므로,
  대여할 때마다 불리는 `Init()`이 초기화 위치로 맞다.
- `Update` / `OnTriggerStay`에 provider null 가드 추가

## 5. 작업 중 발견한 문제와 처리

### 프리로드가 풀 인스턴스를 파괴하던 문제
`FireBolt`/`FirePillar`가 `Start()`에서 `Destroy(gameObject, lifeTime)`를 예약하고 있었다.
프리로드가 인스턴스를 켜는 순간 `Start`가 돌아 파괴가 예약되고, `Destroy(obj, t)`는 비활성화해도 취소되지 않는다.
즉 프리로드 `lifeTime`초 뒤에 풀 전체가 사라진다.
→ `Destroy` 제거 + 수명을 풀로 이관해 해결.

### `FirePillar.Start()`의 NullReferenceException
프리로드가 인스턴스를 켜면서 `Start()`가 도는데 `Init()`은 아직 안 불린 상태라
`currentCharacterProvider`가 null이었다 (`FirePillar.cs:42`, Tracking 모드 `SetDestination`).
→ 초기화를 `Init()`으로 옮기고 가드 추가.

### `wisu.skillPool` NullReferenceException
`WisuAttackPatternA1.cs:43`. 인스펙터의 Skill Pool 슬롯이 비어 있어서 났다. 코드 문제 아님.

### 에디터 예외 (`GameObjectInspector`, `SerializedObjectList`)
스택이 전부 `UnityEditor.*`이고 프로젝트 스크립트가 없다. 파괴된 오브젝트를 인스펙터가 계속 그려서 나는 에디터 전용 예외로, 게임 로직과 무관하다.

## 6. 씬 세팅 절차

1. 씬에 빈 오브젝트를 만들고 `WisuSkillPool`을 붙인다 (보스 오브젝트에 붙여도 된다).
2. `entries`에 6줄을 채운다 — skill / prefab / count / lifeTime.
   같은 프리팹을 쓰는 줄은 한쪽에 총량을 몰아넣고 나머지를 0으로 둬도 큐를 공유한다.
   단 전부 0이면 프리로드 대상이 비어 스터터 방지 효과가 사라진다.
3. 보스 인스펙터의 `Wisu Main Re > Skill Pool` 슬롯에 1번 오브젝트를 연결한다.

프리로드 등록은 별도 작업이 필요 없다.
`AttributeInjector`가 `FindObjectsByType<MonoBehaviour>(FindObjectsInactive.Include, ...)`로 씬 컴포넌트를 전부 훑어
인터페이스별로 등록하므로, 씬에 올라가 있기만 하면 `EventPreloadRender`가 `IPreloadTargetProvider`로 잡는다.
다만 보스가 런타임 스폰이면 주입 타이밍을 놓치므로 씬에 미리 존재해야 한다.

## 7. 남은 것

- **FirePillar Tracking 모드의 재사용**: NavMeshAgent가 켜진 상태에서 `transform` 위치만 바뀌므로 워프가 필요할 수 있다. 문제가 보이면 `Init()`에 `navMeshAgent.Warp(transform.position)` 한 줄.
- **dangerZone 4종**: 아직 `Instantiate`/`Destroy`. 필요하면 같은 방식으로 풀에 넣을 수 있다.
- **삭제된 lifeTime 기본값**: `FireBolt`/`FirePillar`의 `lifeTime` 필드를 지우면서 각 프리팹 인스펙터에 들어 있던 값이 유실됐다. 풀 entry의 `lifeTime`에 다시 입력해야 한다.
